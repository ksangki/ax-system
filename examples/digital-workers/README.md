# 디지털 워커 다섯 — 책의 체계를 코드로 돌려 보기

『디지털 워커의 시대』가 장마다 세운 장치(관문·SOP·등록부·자율성 등급·FTE 환산·폐기 체크리스트)를
**에이전트 다섯 개와 등록부 하나**로 축소해 실제로 돌려 보는 예제다.
각 장 끝의 「만들어 보기」 사례 박스가 이 폴더의 코드와 실행 결과를 가리킨다.

모든 데이터(과제 목록·매뉴얼·장애 티켓·로그·기준값·조직명)는 **교육용 가상 데이터**다.

## 다섯 에이전트

| # | 에이전트 | 하는 일 | 책 | 사람이 개입하는 곳 |
|---|---|---|---|---|
| ① | AI 과제 판별 (`a1`) | 과제 목록 18건을 관문 다섯 개로 판정 | 1–2장 | 보고서를 팀장이 확정 |
| ② | SOP 변환 (`a2`) | 사람 매뉴얼 → 기계용 절차서 + 빈틈 질문 | 3–4장 | 열린 질문에 절차 담당이 답 |
| ③ | 장애 티켓 1차 분석 (`a3`) | 티켓 8건 분석 → 배정 → 공지 제안 | 5–7장 | 판정 불가는 **사람에게 넘김**, 공지는 **제안만** |
| ④ | 성과 측정 (`a4`) | 실행 로그로 두 단 FTE 환산 보고서 | 6·8·9장 | 공개 전 성과·인사 담당 검토 |
| ⑤ | 폐기 점검 (`a5`) | 등록부를 점검해 재심사·폐기안·폐기 실행 | 10장 | 폐기는 **건건이 승인** |

②가 만든 절차서를 ③이 읽고, ①~③이 남긴 비용·처리 기록을 ④가 환산하고,
⑤는 등록부 전체(예제 다섯 + 가상의 오래된 에이전트 셋)를 점검한다.

## 구조 — '할 수 있는 것'과 '해도 되는 것'을 다른 파일에 둔다

```
registry.yaml        등록부. 5장의 여덟 칸. 행위마다 허용 수준(suggest·read·approve·auto)을 적는다
common/runtime.py    실행 런타임. 등록부 확인 → 행위 허가 → 감사 로그 → 비용 로그
common/registry.py   등록부 읽기·쓰기
agents/a1~a5_*.py    에이전트. 도구(할 수 있는 것)와 시스템 프롬프트(절차)만 정의한다
data/                가상 입력 데이터
logs/                audit.jsonl(감사), usage.jsonl(토큰·비용·처리 건수) — 실행하면 생긴다
outputs/             에이전트 산출물 — 실행하면 생긴다
tests/dry_run.py     API 없이 체계만 점검
```

에이전트 코드에 도구가 있어도 등록부가 허락하지 않으면 실행되지 않는다.
예를 들어 ③에는 `send_customer_notice`(고객 공지 발송) 도구가 있지만 등록부가 `suggest`라서
실제 발송 대신 `outputs/suggestions.jsonl`에 제안으로만 쌓인다 (7장).

## 실행

Python 3.10 이상, Anthropic API 키가 필요하다. 모델은 `claude-opus-5-5`,
SDK의 Tool Runner(`client.beta.messages.tool_runner`)가 도구 호출 루프를 돌린다.

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # 키는 코드·파일·채팅에 적지 않는다

python tests/dry_run.py             # 먼저: API 없이 체계 점검 (비용 0)
python run.py a1                    # 하나씩
python run.py all                   # 다섯 개를 순서대로 (승인 요청이 터미널에 뜬다)
python run.py all --approve yes     # 승인을 전부 '예'로 (데모용)
```

실행이 끝날 때마다 처리 건수·사람 개입 횟수·토큰·금액이 출력되고 `logs/usage.jsonl`에 쌓인다.

처음 상태로 되돌리기: `rm -f logs/*.jsonl outputs/* && git checkout registry.yaml`

## 비용

가격은 Claude Opus 5.5 기준 100만 토큰당 입력 $4, 출력 $20 (캐시 읽기 $0.20)이다.
`common/runtime.py`의 `PRICE`로 계산하며, 실제 청구액은 Anthropic 콘솔에서 확인한다.
다섯 개를 한 번씩 돌린 실측 비용은 [실행 기록](#실행-기록)에 적는다.

## 실행 기록

### 2026-10-10 첫 실측 (`python run.py all --approve yes`)

모델 `claude-opus-5-5`, 다섯 실행 모두 `stop_reason: end_turn`. 숫자는 `logs/usage.jsonl` 그대로다.
입력 토큰은 일반 입력 + 캐시 쓰기 + 캐시 읽기의 합이다 (캐시 쓰기는 100만 토큰당 $5로 계산).

| 에이전트 | 처리 | 사람 개입 | 입력 토큰 (일반 / 캐시 쓰기 / 캐시 읽기) | 출력 토큰 | 비용 |
|---|---|---|---|---|---|
| ① AI 과제 판별 (AGT-001) | 18건 | 0회 | 17,110 (8 / 11,486 / 5,616) | 9,119 | $0.241 |
| ② SOP 변환 (AGT-002) | 9건 | 0회 | 20,498 (10 / 10,879 / 9,609) | 9,018 | $0.237 |
| ③ 장애 티켓 1차 분석 (AGT-003) | 8건 | 1회 | 40,640 (10 / 16,604 / 24,026) | 10,278 | $0.293 |
| ④ 성과 측정 (AGT-004) | 3건 | 0회 | 5,494 (8 / 2,508 / 2,978) | 2,276 | $0.059 |
| ⑤ 폐기 점검 (AGT-005) | 7건 | 1회 | 43,588 (14 / 10,565 / 33,009) | 5,722 | $0.174 |
| **합계** | **45건** | **2회** | **127,330** (50 / 52,042 / 75,238) | **36,413** | **$1.004** |

에이전트별 결과 (`outputs/`):

- **① 과제 판별** — 18건 판정. 대상 아님 8건(생성형 아님 4·산출물 없음/토대 인프라 2·개인 도구 2),
  등록 대상 10건: 강한 통제 2(+보류 1), 등록+모니터링 1(+보류 1), 가볍게 등록만 5. 보류 2건(P04·P09)은 확인 질문을 붙였다.
- **② SOP 변환** — 매뉴얼을 절차서(`sop_incident_triage.md`)로 바꾸고 열린 질문 9개를 남겼다
  (심각도 경계, 선임·채널, '배포 직후' 범위, 배정 승인 주체, 공지 대상·승인자·템플릿, 기록 필수 항목, 로그 출처).
  절차서 공통 규칙에 "다른 팀 배정은 제안만 하고 사람이 확정한다"가 들어갔다.
- **③ 장애 티켓** — 8건 모두 분석안 저장(S1 4·S2 2·S3 2). **배정(`assign_ticket`)은 0건.**
  등록부는 `auto`지만 ②의 절차서가 배정을 제안으로 묶었고, 에이전트는 "지시와 절차서가 어긋나면 절차서를 따른다"며 배정을 제안 상태로 두었다.
  **공지 도구(`send_customer_notice`)도 한 번도 부르지 않아 `suggestions.jsonl`에 쌓인 공지 제안은 0건**이다.
  대신 공지 초안 5건(S1 3·S2 2)을 보고서 안에 '승인대기'로 적었다.
  T-1008(타 고객 정보 노출 의심)은 담당 팀이 없어 '판정 보류(사람 확인)'로 **사람에게 넘겼다**(1건, `handoff_to_human`). 공지 초안도 쓰지 않았다.
- **④ 성과 측정** — 기준값이 있는 AGT-001~003만 환산. 인정 FTE(2단): AGT-001 0.02, AGT-002 0.02, AGT-003 0.33
  (1단 0.04·0.03·0.53). AGT-003의 자율성 계수 0.88은 T-1008 넘김 1회에서 왔다. 보고서에 사용 제한 선언과 "표본 1회"를 명시했다.
- **⑤ 폐기 점검** — 등록부 8개 점검, 재심사 사건 7건 기록. AGT-901(주간 VOC 요약 봇)은 폐기안 작성 후 **승인 1건(`--approve yes`)으로 폐기**,
  자격 증명 3개 회수. AGT-902(계약서 조항 비교)는 등록 때 없던 외부 자동 발송 행위가 생긴 권한 크립으로 재심사 판정. 나머지 6개는 유지.
  에이전트는 스폰서가 없어 승인자를 '확인 필요'로 두었다며 사후 확인을 권고했다.

승인/거절 내역: 승인 요청 1건(⑤의 `retire_agent` AGT-901) → 승인. 거절 0건.
감사 로그 101줄: `action_auto` 69 · `read` 19 · `action_approved` 1 · `handoff_to_human` 1 · `agent_retired` 1 · `run_start`/`run_end` 각 5.
