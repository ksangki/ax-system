# 장애 티켓 1차 대응 매뉴얼 (서비스운영팀, 2024년 개정)

> 교육용 가상 문서다. 사람이 쓴 매뉴얼이 흔히 그렇듯 일부러 빈틈을 남겨 두었다.

## 1. 접수
- 관제 화면에 새 티켓이 뜨면 바로 연다.
- 티켓 내용과 관련 로그를 확인한다.

## 2. 심각도 판단
- 고객 영향이 크면 심각(S1)으로 본다.
- 일부 고객만 영향이 있으면 S2, 영향이 거의 없으면 S3로 둔다.
- 애매하면 선임에게 물어본다.

## 3. 원인 확인
- 로그에서 에러를 찾아 원인을 추정한다.
- 최근 배포가 있었는지 확인한다. 배포 직후 장애는 대부분 배포가 원인이다.

## 4. 담당 팀 배정
- 원인에 맞는 적절한 팀에 배정한다.
  - 네트워크 문제 → 네트워크운영팀
  - 서버·애플리케이션 → 플랫폼운영팀
  - 결제·요금 → 빌링운영팀
  - 인증·로그인 → 계정플랫폼팀
- 잘 모르겠으면 플랫폼운영팀에 넣는다.

## 5. 고객 공지
- 심각한 장애는 고객 공지를 낸다.
- 공지 문구는 상황에 맞게 작성한다.

## 6. 기록
- 처리 내용을 티켓에 적절히 남긴다.
